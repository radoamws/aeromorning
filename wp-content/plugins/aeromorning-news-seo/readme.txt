Google News XML sitemap + NewsArticle structured data for a WordPress multisite news network. Free, self-contained reimplementation of the two core features of Yoast News SEO.

== Description ==

Built for a WordPress **multisite** installation publishing news in more than one language (e.g. `example.com/` in French, `example.com/en/` in English), where each edition needs its own sitemap, its own `<news:language>`, and its own publication name.

It ships exactly two things, well:

1. **A Google News XML sitemap** at `/news-sitemap.xml`, containing only articles published within the last 48 hours (configurable), per the [Google News sitemap spec](https://developers.google.com/search/docs/crawling-indexing/sitemaps/news-sitemap). Capped at 1,000 URLs as required by the spec, cached a few minutes, and invalidated automatically whenever a post is published, edited or trashed.
2. **NewsArticle structured data** instead of the generic `Article` type.
   - If **Yoast SEO** is active, no second JSON-LD block is added — the plugin hooks into Yoast's existing schema graph and switches its `@type` from `Article` to `NewsArticle` for the post types you choose.
   - If Yoast SEO is not active, a minimal standalone `NewsArticle` JSON-LD block is output instead.

Everything else Yoast's paid News SEO add-on offers that made sense to include is here too: per-post **exclude from Google News**, **genres** (PressRelease, Satire, Blog, OpEd, Opinion, UserGenerated), **keywords** (falls back to categories), **stock tickers**, and an **image** entry in the sitemap for the featured image.

= What this plugin intentionally does NOT claim =

Neither a news sitemap nor `NewsArticle` markup guarantees inclusion in Google News, Top Stories or Discover — Google decides that separately, based on content policies and (for Google News specifically) Publisher Center enrollment. This plugin only makes sure the technical signals are correct so a real newsroom is never excluded on a technicality.

== Multisite behaviour ==

* Network-activatable, but **every setting is per-site**, not shared network-wide — this is what makes FR/EN correct: each edition keeps its own publication name, language code, included post types, excluded categories and sitemap.
* Activating network-wide seeds sensible defaults (site name as publication name, language auto-detected from the site's locale) on every existing site, and on any site created afterwards.
* Deactivating flushes rewrite rules on every site so `/news-sitemap.xml` cleanly 404s instead of leaving a stale route.

== Installation ==

1. Upload the `aeromorning-news-seo` folder to `/wp-content/plugins/`.
2. Network Activate (or activate per-site).
3. On **each** site (both the FR root site and the `/en/` sub-site), go to **News SEO** in wp-admin and confirm the publication name and language, then save once to flush rewrite rules.
4. Visit `/news-sitemap.xml` on each site to confirm it renders valid XML.
5. In Google Search Console, submit `news-sitemap.xml` for each property (or, if you also use Yoast's own sitemap, it is auto-listed inside `sitemap_index.xml`).

== Frequently Asked Questions ==

= Does this replace Yoast SEO? =
No. It's a small, focused add-on. If Yoast SEO is active it reuses Yoast's existing Article schema output rather than duplicating it; the sitemap is always generated by this plugin since Yoast SEO Free has no news sitemap.

= Why isn't my site in Google News after installing this? =
Technical markup is necessary but not sufficient. Google News inclusion also depends on Publisher Center enrollment and content policy compliance — check Search Console's Google News report separately.

= What happens to the freshness window if I set it above 48 hours? =
Google's crawler generally ignores anything older than 2 days in a news sitemap regardless of what the file contains, so values above ~48h have little practical effect; the field is capped at 72h.
